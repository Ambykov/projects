# ADR-0002: Протокол измерений для сравнения STT-моделей

**Статус:** Accepted
**Дата:** 2026-10-28

## Контекст

Между прогонами без прогрева latency варьируется на ~10% (0.2422 → 0.2194), что превышает ожидаемую разницу между моделями.

## Проблема

При сравнении gigastt vs T-one без фиксации протокола сравнение будет шумным — разница в latency может быть вызвана не моделью, а системной нестабильностью.

## Решение

Зафиксировать протокол измерения:

| Параметр | Значение |
|----------|----------|
| warmup | 2 прогона (не учитываются) |
| measured | 3 прогона |
| aggregation | median по измерительным прогонам |
| Системные метрики | nproc, load_avg_1m записываются в metrics.json |

## Последствия

- bench.py поддерживает флаги `--warmup N` и `--repeat N`
- metrics.json содержит блок `protocol` с параметрами измерения
- Summary включает latency_std_sec, latency_min/max/median для оценки разброса
- Сравнение моделей ведётся по медиане, а не по одиночному прогону

## Методика замера TTFP (для шлюза)

| Параметр | Значение |
|----------|----------|
| Файлы | 10 файлов из manifest.tsv |
| Размер чанка | 100 мс (1600 сэмплов @ 16 кГц) |
| Соединение | Отдельное WS на каждый файл |
| Прогрев | 1 прогон (не учитывается) |
| Замер | 5 прогонов подряд |
| Агрегация | median по файлам внутри прогона, затем median/std по 5 прогонам |
