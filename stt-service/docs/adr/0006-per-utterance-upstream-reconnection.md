# ADR-0006: Per-utterance upstream reconnection для многофазовых сессий

**Статус:** Accepted
**Дата:** 2026-10-29

## Контекст

GigaSTT не поддерживает long-lived WebSocket-сессии — закрывает соединение после `stop` → `final`. Для голосового ассистента нужна возможность отправлять несколько реплик в рамках одной сессии без переподключения клиента.

## Решение

Архитектура «одна реплика — одно upstream-соединение»:

1. **Long-lived клиентское соединение:** Клиент подключается к `/ws/stt`, соединение остаётся открытым на всю сессию диалога
2. **Per-utterance upstream:** На каждую реплику шлюз открывает новое upstream-соединение к GigaSTT
3. **Протокол:**
   - `{"type": "end_of_utterance"}` — конец реплики
   - `{"type": "stop"}` — конец сессии

## Альтернативы

| Подход | Проблема |
|--------|----------|
| Single upstream для всей сессии | Не работает, GigaSTT закрывает после `stop` |
| Переподключение клиента на каждую реплику | Увеличивает latency первой реплики |
| REST API для каждой реплики | Нет streaming, выше задержка |

## Последствия

- Upstream connect: 4 мс (ADR-0016)
- Время до final (TTFT) для 1-сек реплики: ~250 мс
- TTFP первой реплики: 121 мс
- Клиентский SDK должен отправлять `end_of_utterance` после каждой реплики (VAD на клиенте)

**Примечание:** Multi-utterance починен 2026-10-30 (сброс `audio_queue=None`, `current_rep_task=None` после `await current_rep_task`), см. инцидент `docs/incidents/2026-10-29-refactor-regression.md` (Resolved).
